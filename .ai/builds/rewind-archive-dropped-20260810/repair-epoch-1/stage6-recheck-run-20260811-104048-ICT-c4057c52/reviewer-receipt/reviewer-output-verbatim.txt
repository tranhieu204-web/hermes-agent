## 4. Ruling on the disclosed B-1 guard limit — **wider than admitted**

The design is right: the durable side is projected to mirror `_rows_to_conversation` exactly, `api_content` stays verbatim and byte-exact, and `expected_history` is deliberately not re-normalized. I confirmed M02 (`NORMALIZE_EXPECTED_SIDE_TOO`) is a real mutation of the naive fix, and its test genuinely catches it — the drift half sets `drifted_expected[1]["content"] = "answer text\n"` (raw, un-projected), which under the naive fix would normalize into agreement and pass. The repair did **not** buy its pass by weakening the comparison.

The problem is the stated cost. `sanitize_context` is not whitespace normalization — it deletes whole spans (`agent/memory_manager.py:174-179`). Six live scenarios against real `SessionDB` instances:

| Scenario | Result |
|---|---|
| S1 trailing `\n` on assistant turn → `/retry` path | **REWIND OK** — B‑1 fixed |
| S2 genuine content drift | **RewindHistoryConflict** — fails closed |
| S3 whitespace-only drift | ACCEPTED — the disclosed limit |
| **S4 `<memory-context>EXFIL: arbitrary payload</memory-context>` injected, no sidecar** | **ACCEPTED — 66 bytes undetected** |
| S5 same injection **with** sidecar present | **RewindHistoryConflict** — sidecar does close the gap where present |
| **S6 `[System note: …]` span removed, no sidecar** | **ACCEPTED — undetected** |

So "*api_content closes that byte-fidelity gap wherever the sidecar is present*" is **accurate** (S5 proves it). The under-scoping is in *how often it is present* and *what escapes when it is not*:

- The compensating rule that stamps a sidecar exactly when `sanitize_context(content).strip() != content.strip()` exists at **one site**: `run_agent.py:2171`. The other three persistence sites — `gateway/session.py:3092`, `slash_commands.py:4261`, `hermes_cli/cli_commands_mixin.py:979` — use `extract_api_content_sidecar`, which only forwards an already-present sidecar.
- More fundamentally, that rule governs how *legitimate* rows are written. It cannot help in the case the guard exists for: a row written as ordinary content (correctly, no sidecar) that later **drifts** to contain a fence. That is precisely S4, and no write path is involved.
- Sidecars are otherwise sparse by construction: `compose_user_api_content` returns `None` when nothing is injected, stamps only the current turn's **user** message, and `drop_stale_api_content` removes it on every content-rewrite path.

**Fair mitigation, which I want on the record:** `_rows_to_conversation` sanitizes on read, so an undetected injected span is also invisible to the model on replay — model-visible history is identical by construction. The exposure is to durable-record and export fidelity, not model behaviour. That caps severity at **MEDIUM**, not HIGH. And the trade is genuinely forced: `expected_history` arrives already projected, so raw-byte comparison on that side is impossible.

The fix is small — correct the `guard_limit` wording to "drift invisible to `sanitize_context(...).strip()`, which includes memory-context and system-note spans, not only whitespace," and add a test pinning the fence-content case.
